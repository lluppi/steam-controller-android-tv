# P3.S6 — the app itself on the Shield: verified

Run 2026-09-20/21 on the Shield TV (`$SHIELD`; see the private notes for the address).
Fork build `com.steamcontroller.android.debug` (debug builds install side by side, see
`applicationIdSuffix` in `app/build.gradle.kts`), controller connected over Bluetooth.

## What Android made of them

```text
EventHub: New device: id=17, path='/dev/input/event6', name='Microsoft X-Box 360 pad',
          keyLayout='/system/usr/keylayout/Vendor_045e_Product_028e.kl'
InputReader: Device added: id=17, name='Microsoft X-Box 360 pad', sources=0x01000511
EventHub: New device: id=18, path='/dev/input/event7', name='Steam Controller Mouse'
InputReader: Device added: id=18, name='Steam Controller Mouse', sources=0x00002002
EventHub: New device: id=19, path='/dev/input/event8', name='Steam Controller Keyboard',
          keyLayout='/system/usr/keylayout/Generic.kl'
InputReader: Device added: id=19, name='Steam Controller Keyboard', sources=0x00000301
```

- gamepad `0x01000511` = SOURCE_GAMEPAD | SOURCE_KEYBOARD | SOURCE_JOYSTICK
- mouse `0x00002002` = SOURCE_MOUSE | SOURCE_CLASS_POINTER
- keyboard `0x00000301` = SOURCE_KEYBOARD | SOURCE_DPAD — so the sidecar keyboard does
  reach `INPUT_DEVICE_CLASS_DPAD`, which is what the consumer "Menu Pick → KEY_SELECT"
  mapping in `SIDECAR_KEYS[MK_DPAD_CENTER]` was for. The Leanback IME needs that class.
- Android matched `Vendor_045e_Product_028e.kl` for the gamepad, so this build is
  interchangeable with the uinput one for keylayouts and RetroArch autoconfig.

## Frame flow — report packing verified in motion

Live `getevent -lt` on the gamepad node, over a period with no button presses:

```text
   380 EV_ABS ABS_RY
   311 EV_ABS ABS_RX
    84 EV_ABS ABS_HAT0Y
    73 EV_ABS ABS_Y
    63 EV_ABS ABS_X
     6 EV_ABS ABS_HAT0X
   598 SYN_REPORT
     0 EV_KEY
```

Values are small and correctly signed around centre (`ABS_Y 0000002b`, `000000c6`,
`ffffff0e`, `fffffff…`), which is what a byte-order or offset error would destroy —
those would surface as garbage near ±32500. So the int16 little-endian axis packing and
the offsets in `sendFrame` are right, and the hat field reaches `ABS_HAT0X/Y` as the
uinput backend declared them.

## Verified vs still open

Verified on hardware:

- backend selection picks uhid because `/dev/uinput` is denied; the service runs in the
  shell UID (`ps` shows `com.steamcontroller.android.debug:uinput` under user `shell`)
- all three devices exist, are classified correctly, and Android attaches them
- frames flow continuously; sticks and hat confirmed with correct values
- the controller connects over Bluetooth and `injection mode = UHID`
- the notification carries the "→ next profile" action, which only exists in a
  virtual-device mode

Still open:

- **no `EV_KEY` observed yet** — button bit packing is verified by construction (the
  `XBOX_BUTTONS` index table) but has not been seen in motion. Press every face button,
  bumper, dpad direction and both stick clicks while capturing.
- **`ABS_Z` / `ABS_RZ` (triggers)** not yet seen — pull both triggers.
- **mouse/keyboard sidecar** — no `REL_X`/`REL_Y` captured yet. Move the right trackpad
  and check the cursor moves on the launcher, and that the left pad scrolls.
- RetroArch gameplay end to end.
- Rumble is expected to be unavailable on uhid (`hid-generic` implements no force
  feedback for these descriptors): the Calibration screen disables the test button and
  says so. That is PLAN P6, not a regression.

## UI defects found and fixed during this test

1. Radio labels ("Xbox 360", "Xbox One") rendered black. The theme used a DayNight parent
   with a hardcoded dark palette, so off night-mode it resolved to the light scheme. Now
   an always-dark theme. Confirmed white on the TV.
2. Scrolling left ghost trails of the previous content. The root ScrollView had no
   background, so vacated regions depended on the window background being repainted. Now
   paints `@color/window_bg`. Confirmed clean on the TV.
3. Focus order: DOWN from the Bluetooth device row skipped "Start Service" and landed on
   "Debug HID"; UP from "Debug HID" skipped it too and hit the refresh button. Cause: the
   dropdown's internal end icon (`text_input_end_icon`) is its own focus stop, so the
   field's focus links never applied. The icon is now out of the focus order and the hops
   are explicit (`nextFocusDown`/`nextFocusUp`), including memory for which action card
   you came from. Verified by walking focus on the device.
